# Infrastructure configuration
The authenticated Infrastructure tab includes **Live routing & infrastructure configuration**.
Use Refresh to query the active controller through the proxy and check both production routers. Opening the panel performs no mutation.
The private Ops Desk repository owns desired nonsecret settings in infra-config.json. It is separate from live provider state. Keep unknown email addresses empty until the workspace owner confirms them. Edit the appropriate nodes or workers entry, rebuild with python build_ui.py, and review the change through Git.
The existing sh01-fastapi-server repository owns the two worker-router implementations and watchdog linked in the inventory. The infra-control implementation has no verified source link in this checkout. Run the source capture command below for the actual deployed JavaScript before managing that code. Example Wrangler files in the backend are examples, not the current binding state.
## Bindings on the Ops Desk Cloudflare Worker
The live controller view reuses CONTROL_PLANE_API_KEY. Provider modifications additionally require INFRA_CONFIG_ADMIN_KEY (separate secret, entered by an operator). Render updates require the workspace API key named by the target's key field. For controller targets set INFRA_SERVICE_ID_D0YA and INFRA_SERVICE_ID_MTWU to their actual Render service IDs. Before writing, Ops Desk compares the provider service URL to the selected node. An unknown or differing URL stops the write.
For Cloudflare settings, configure INFRA_CF_ACCOUNT_ID and INFRA_CF_TOKEN with access to the intended scripts. Use read-only provider credentials for a view-only installation. Configure bindings individually, leaving existing Ops Desk bindings in place.
Preview and Apply operate on one reviewed key on one target. Apply re-reads the provider setting and rejects a changed preview. Provider APIs offer no transaction across services. Avoid concurrent edits on the same target. Confirm runtime adoption separately. Render writes use the single direct service env-var endpoint; linked env groups have separate ownership. Cloudflare applies the selected plain-text binding and inherits the other named bindings. Use this path on Workers with a single deployed version; do not use during staged rollouts.
## Other workbook
Select the exact target. For a complete replacement paste its current KEY=value column in Manual workbook export. Copy merges desired rows by exact key, preserves unmanaged rows including credentials, and appends missing settings. With an empty input it copies managed rows only. Existing secret values stay in your browser; supply new secret rows locally in the input before copying. Never commit credentials, pasted workbook columns, or keys in vars. The app has no integration with this workbook.
## Capture deployed Worker source
From the private Ops repository run python capture_infra_worker.py SCRIPT_NAME. Enter the Cloudflare account ID and token when prompted. This reads the provider source and saves a new untracked file under infra-worker-snapshots; it never overwrites a snapshot. Inspect for embedded credentials before staging. Multipart module bundles are retained intact (.mime) for review. Record only reviewed and sanitized source, never credentials. Add the resulting repository path to the corresponding source field.

For secret-valued Render settings, put only the secret binding name in the target's secrets mapping. The dashboard can reconcile a controller's RENDER_C_API_KEY from the existing Ops Desk RENDER_C_API_KEY binding. The browser receives only comparison state. Manual export requires the operator to provide the actual key row locally. Apply one target at a time. Do not apply identical state just to validate the feature.
